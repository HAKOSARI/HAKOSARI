## Featured engineering project

### [Sakarya Aerospace — Engineering Showcase](https://github.com/HAKOSARI/sakarya-aerospace--engineering-showcase)

[![Showcase CI](https://github.com/HAKOSARI/sakarya-aerospace--engineering-showcase/actions/workflows/showcase-ci.yml/badge.svg)](https://github.com/HAKOSARI/sakarya-aerospace--engineering-showcase/actions/workflows/showcase-ci.yml)
[![Apache 2.0](https://img.shields.io/badge/License-Apache%202.0-blue.svg)](https://github.com/HAKOSARI/sakarya-aerospace--engineering-showcase/blob/main/LICENSE)

An open engineering showcase focused on:

- **Requirements traceability** — linking needs, requirements, cases, evidence, and decisions.
- **Interface change impact** — identifying dependencies and reverification candidates.
- **Evidence applicability** — assessing configuration, provenance, and assumptions.
- **Verification discipline** — Inspection, Analysis, Demonstration, and Test.
- **Human review** — distinguishing automated results from formal engineering approval.

The repository includes a [small executable Python change-impact demonstrator](https://github.com/HAKOSARI/sakarya-aerospace--engineering-showcase/tree/main/examples/change-impact-demo), synthetic example data, unit tests, and GitHub Actions CI.

> **Engineering boundary:** These are educational and synthetic demonstrations, not flight-test, qualification, certification, or customer-program evidence.

## Verification Intelligence — the question I'm exploring

```text
System / Interface Change
          ↓
   Dependency & Impact
          ↓
 Evidence Applicability
          ↓
  REUSE / REVIEW / REVERIFY
          ↓
Verification Method & Case
          ↓
       Evidence
          ↓
Human Engineering Decision
```

The goal is to make verification decisions **more traceable, reproducible, and reviewable** — not to replace engineering authority with a green checkmark.
